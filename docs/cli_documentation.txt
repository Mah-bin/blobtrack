================================================================================
 FILE: main.py — CLI Entry Point (argparse front door)
================================================================================

MODULE OVERVIEW:
    This is the front door of the entire application. When a user types
    "blobtrack <command>" in their terminal, this file receives the input,
    parses it using Python's argparse library, and routes it to the
    correct handler function in commands.py.

    Member 1 - CLI & Integration Lead
    Phase 1: registers all 8 commands, dispatches to commands.py.
    Future commands (add/commit/log/etc) are parsed but stubbed until
    later increments are delivered by other team members.

FUNCTION: build_parser() -> argparse.ArgumentParser
    Constructs the argument parser with all 8 subcommands.

    Global Arguments:
        --version       Prints "blobtrack 0.1.0" and exits.
        --help          Prints the help menu listing all commands.

    Subcommands Registered:
        init            No arguments required.
                        Creates a new blobtrack repository.

        add <filepath>  Requires 1 positional argument: the file path.
                        Chunks, hashes, and stages the file.

        commit -m MSG   Requires -m/--message flag with a string.
                        Saves a snapshot of all staged files.

        log             No arguments required.
                        Displays the chronological commit history.

        checkout HASH   Requires 1 positional argument: the commit hash.
                        Reconstructs and restores a previous version.

        push [remote]   Optional positional argument (default: "origin").
                        Pushes only new/modified chunks to the remote.

        pull [remote]   Optional positional argument (default: "origin").
                        Pulls only missing chunks from the remote.

        gc              No arguments required.
                        Deletes orphan chunks with zero references.

    Design Decision: "required=True" on subparsers
        This forces the user to type a command. Running bare "blobtrack"
        with no command will print an error instead of silently doing nothing.

    Design Decision: "nargs='?' with default='origin'" on push/pull
        This mirrors Git's UX convention where "git push" defaults to
        "origin" if no remote name is specified.

FUNCTION: main() -> None
    The main execution function. Called when the user runs blobtrack.

    Flow:
        1. Calls build_parser() to create the argument parser.
        2. Calls parser.parse_args() to parse the user's terminal input.
        3. Routes to the correct cmd_* function in commands.py based on
           the "cmd" attribute set by argparse subparsers.
        4. Wraps everything in a try/except block:
           - SystemExit is re-raised (so argparse --help and --version
             can exit cleanly).
           - All other exceptions are caught, printed to stderr, and
             the process exits with code 1.

    Entry Point Registration:
        This function is registered as "blobtrack" in setup.py via:
            entry_points={"console_scripts": ["blobtrack=blobtrack.cli.main:main"]}
        This allows the user to type "blobtrack" directly in the terminal
        after installing the package with "pip install -e ."

HELPER: _print_success(msg: str) -> None
    Prints a green success message using the Rich library.
    If Rich is not installed, falls back to plain print().

    Design Decision: Rich Fallback
        The CLI uses a try/except ImportError guard around Rich.
        If Rich is not available (e.g., in a minimal Docker container),
        the tool still works perfectly with plain text output. This
        prevents a hard dependency crash on a cosmetic library.

HELPER: _print_error(msg: str) -> None
    Prints a red error message using the Rich library.
    Falls back to printing to sys.stderr if Rich is unavailable.

FUNCTION: cmd_init(cwd: pathlib.Path | None = None) -> None
    Creates a new blobtrack repository in the current working directory.

    What it creates:
        .blobtrack/             Hidden root directory (like .git/)
        .blobtrack/objects/     Stores compressed chunk blobs named by SHA-256 hash
        .blobtrack/commits/     Stores JSON commit manifests
        .blobtrack/index.db     SQLite metadata database

    Safety Features:
        - Double Init Protection: If .blobtrack/ already exists, the command
          refuses to run and prints an error. It will never overwrite or
          corrupt an existing repository.

        - Directory Validation: Checks that the current path is actually a
          directory before attempting to create the repository.

        - Atomic Rollback: If any step fails (e.g., permission denied on
          creating a subdirectory), the entire partially-created .blobtrack/
          folder is deleted via shutil.rmtree(). The user is never left with
          a half-initialized, broken repository.

        - Permission Hardening: Directories are created with mode 0o700
          (owner read/write/execute only). On Windows this is silently
          ignored but does not cause an error.

    Member 4 Integration:
        The function attempts to import init_db() from blobtrack.storage.index_db.
        If Member 4's storage module exists, it delegates database schema creation
        to init_db(). If Member 4's module is not yet available (ImportError),
        it creates an empty placeholder index.db file instead.

    Args:
        cwd: Optional path override. If None, uses the current working directory.
             This parameter exists primarily for testing purposes.

FUNCTION: cmd_add(filepath: str) -> None
    Increment 2 — Fully implemented. Chunks, compresses, deduplicates and
    stores a file via Member 2 + Member 4 integration.

    What it does (8 steps):
        1. Verify repository exists by walking up parents hunting .blobtrack/
           else "not a blobtrack repository. Run 'blobtrack init' first." (exit 1)
        2. Resolve filepath via pathlib.Path.resolve() (handles relative/absolute,
           spaces) and verify exists + is_file else "file not found"/"not a file"
        3. Open storage handles: LocalStore(repo/.blobtrack/objects) and
           IndexDB(repo/.blobtrack/index.db) (Member 4)
        4. Stream chunks via Member 2: chunk_file_streaming(filepath) ->
           ChunkData(index,offset,length,data) then
           process_chunks(stream,batch 16,workers 8) ->
           ProcessedChunk(index,offset,length,hash,compressed_data) which
           already does hash_bytes(SHA-256) + compress(Zstandard). Never
           loads whole file into RAM, never re-hashes in CLI.
        5. For each ProcessedChunk: has_chunk(hash)? reused++ : store_chunk(
           hash,compressed) -> new++ ; uses atomic tempfile+fsync+move inside
           LocalStore, never writes .blobtrack/objects directly.
        6. Record chunk metadata idempotently: IndexDB.record_chunk(
           hash,uncompressed=len,compressed=len(compressed))
        7. After loop, register file: hash_file_streaming(filepath) for file
           hash + stat size/mtime -> IndexDB.register_file(posix_rel_path,
           file_hash,size,last_modified,status="tracked")
        8. Output via Rich: "Added 'rel' -> N chunks (new, reused, dedup%) [uncompressed -> compressed bytes]"

    Safety Features:
        - Repo/file validation before any I/O, no traceback for normal user errors
        - Path resolved and stored as repo-relative posix (or absolute if outside repo)
        - Empty file raises ValueError -> controlled error
        - Deduplication via has_chunk before store_chunk ensures identical chunks
          produce identical hash and are stored once (tested 10MB 2 chunks ->
          1KB patch -> 1 new 1 reused 50% dedup)
        - Atomic storage via Member 4 LocalStore, DB via IndexDB WAL
        - On storage/DB exception, exits 1 with Error: prefix, does not
          leave half-registered metadata (record_chunk is idempotent)

    Does NOT call MerkleTree/build_tree or save_commit — those belong to
    Increment 3 commit. Does NOT modify core/* or storage/* implementations.

    Args:
        filepath: Path string as typed by user (relative or absolute)
    Returns:
        Exits 0 on success, 1 on user/storage error. Prints success via
        _print_success or error via _print_error.

FUNCTION: cmd_commit(message: str) -> None
    Increment 3 — Fully implemented. Builds Merkle Tree from current tracked
    files, computes delta vs parent, and persists commit via Member 3+4.

    What it does (9 contracts, 8 steps):
        1. Validate message non-empty else "commit message cannot be empty"
           (exit 1) and repo exists via _find_repo_root() walk else "not a
           blobtrack repository"
        2. Open IndexDB(repo/.blobtrack/index.db) + LocalStore(objects)
           (Member 4) and list tracked files via IndexDB.list_files() sorted
           by path posix for deterministic repo-level order (Contract 1,9).
           If none -> "no tracked files. Run 'blobtrack add' first."
        3. For each tracked file (e.g., a.txt->[A1,A2] b.txt->[B1,B2,B3]),
           resolve disk path repo/rel else absolute, stream via Member 2
           chunk_file_streaming(path) -> ChunkData then
           process_chunks(stream,batch 16/workers 8) -> ProcessedChunk
           (hash,compressed). Collect combined_hashes ordered by file path
           then chunk index (Contract 3) and file_chunk_mappings
           {file_path,chunk_hash,offset,length,order,uncompressed,compressed}
        4. Build repo-level Merkle Tree: build_tree(combined_hashes)->
           MerkleNode (Contract 4, odd level promotes not duplicates, single
           chunk is root) -> merkle_root = root.hash, tree_data =
           serialize_tree(root) JSON string (Contract 4)
        5. Parent handling (Contract 6): latest = get_latest_commit()
           parent_hash = latest.commit_hash else None. Deserialize parent
           tree_data via deserialize_tree(json.dumps(dict) if dict else str)
           for delta. First commit parent None.
        6. Commit hash (Contract 7): CURRENT IMPLEMENTATION pending team
           approval - deterministic SHA-256 of
           f"{merkle_root}:{message}:{timestamp}:{parent or ''}".encode()
           via hash_bytes() -> commit_hash, timestamp = time.time(). Team
           to confirm if author/tree_data should be included. Currently
           verified working for log/checkout chain, freeze after approval.
        7. Delta for logging (Contract 5): if parent_tree exists
           compute_delta(parent_tree,new_tree) -> {added,removed,unchanged}
           display "| delta: +N -M =K" (positional prune, by_set reserved
           for push/pull per Member 3 - Member 3 to confirm)
        8. Persist atomically via Member 4 IndexDB.save_commit(
           commit_hash,message,parent_hash,author=None,timestamp,
           merkle_root_hash,tree_data,file_chunk_mappings) which inserts
           commits + chunks (INSERT OR IGNORE) + chunk_refs (offset/length/
           order, FK CASCADE). Handles JSON tree_data serialization internally.
           Wraps StorageError -> exit 1, never leaves half commit.

    Contracts Satisfied:
        - Current state = tracked files ordered posix (Contract 1)
        - Repo Merkle = concatenation of per-file ordered hashes (Contract 2)
        - Chunk order = file path sorted + chunk.index (Contract 3)
        - Merkle API build_tree/root.hash/serialize (Contract 4)
        - Delta compute_delta (Contract 5)
        - Parent None/first else latest (Contract 6)
        - Commit hash deterministic SHA-256 (Contract 7)
        - save_commit signature exact (Contract 8)
        - Multi-file snapshot coherent (Contract 9)

    Safety: message/repo/file validation first, no traceback for user
    errors, handles missing tracked file on disk by skipping with warning,
    does NOT re-implement CDC/hash/compress/Merkle. Outputs via Rich
    "Committed <12> - N file(s), M chunks, root <12>... | delta ... - \"msg\""
    plus dim parent link. Tested: first commit parent None, second same file
    same root 01a19c parent link, third modified root 348a7d delta +1 -1.

    Args:
        message: Commit message string from -m/--message (required by argparse)
    Returns:
        Exits 0 on success, 1 on validation/storage error. Closes IndexDB.
    Staged implementation: first commit -> second parent -> delta (3C-3E).
